# MDUT-CLI 命令面规格（v1.0 · M0 冻结）

> 本文是 docs/2 §4 的**冻结落地版**，是 `cli/` 包 `CommandSpec` 表与 `cli/SKILL.md` 的单一事实源。
> 冻结后任何词汇/参数/退出码变更必须：改本文 → 改 CommandSpec 表 → 改 SKILL.md（不抄参数）→ CHANGELOG 记录。
> 实施规格（架构/里程碑/风险）见 [docs/2.CLI二开实施方案.md](./2.CLI二开实施方案.md)；本文只管「命令面契约」。

## 1. 全局约定

### 1.1 调用形式

```
mdut [--task NAME] [--tasks-root DIR] [--format json|text] [--timeout SEC]
     [--proxy socks5://[user:pass@]host:port] [-c ENC] [--sql] <command> [args...]
# 等价 java -jar mdut.jar <同参数>（wrapper cli/mdut 负责task 解析与 chdir）
```

| 全局 flag | 缺省 | 说明 |
|---|---|---|
| `--task NAME` | `$MDUT_TASK`，再缺省 `default` | 任务隔离目录 `tasks/<task>/`；wrapper 已解析并以 `-Dmdut.task` 传入；直跑 jar 时本 flag 仍可显式覆盖 |
| `--tasks-root DIR` | `./tasks`（wrapper chdir 后即 `<task目录>/tasks` 不存在，回退 jar 目录？——**冻结为 `./tasks`，直跑 jar 时=当前目录 tasks/；wrapper 场景=task 目录内 `tasks/` 不使用**） | 仅 `task list` 等管理命令关心；实现落 `Util.Tasks` 常量 |
| `--format json\|text` | `json` | text 模式输出 `[+]/[-]/[*]` 前缀文本（人类调试用）；json 模式 stdout 恒一行信封 |
| `--timeout SEC` | `5` | Dao 连接/套接字超时参数（秒）；CLI 看门狗 = `timeout+5s` 兜底强制退出。**超时归类**：异常链含 `SocketTimeoutException`/超时关键词 → exit 4，其余目标失败 → exit 3 |
| `--proxy socks5://...` | 无 | **仅入站**：经既有 SOCKS5 连目标库；出站枢轴不支持（docs/2 §6） |
| `-c ENC` | `""` | 目标回显编码；`""` 保持 Dao 内建缺省（mssql=GB2312 现网行为，其余 UTF-8） |
| `--sql "<sql>"` | — | 兼容形式：无子命令且带 `--sql` 时等价 `sql --id <id> "<sql>"`（`--id` 必带） |
| `--help` / `help [command]` | — | L1 总览表 / L2 单命令参数表；尾部附免责声明 |
| `--version` / `version` | — | 版本信封 |

### 1.2 退出码（全部命令逐项可触发）

| 码 | 语义 | 触发样例 |
|---|---|---|
| `0` | 成功 | 一切正常 |
| `2` | 用法错误 | 未知命令 / 缺必填 flag / task 名非法 / `--sql` 无 `--id` / JSON 参数解析失败 / 无参调用 |
| `3` | 目标连接或执行失败 | 认证失败 / 网络不可达 / SQL 报错 / 目标函数缺失且自动部署失败 |
| `4` | 超时 | 看门狗超时（`--timeout`） |
| `5` | task 写锁竞争 | 变异类命令与另一进程 flock 冲突（§5） |

### 1.3 输出契约

- **stdout 恰好一行 JSON 信封**（`--format json`，默认）：
  - 成功：`{"ok":true,"task":"eng1","tool":"exec","id":"3","text":"uid=0(root) ...","data":{...}}`
  - 失败：`{"ok":false,"task":"eng1","tool":"exec","id":"3","error":"...","hint":"可操作建议"}`
  - 字段序固定 `ok,task,tool,id,text,error,hint,data`（存在才出）；`data` 为结构化结果对象（尽力而为，失败回退仅 `text`）。
- **日志一律 stderr**，格式沿用 `[*] yyyy-MM-dd HH:mm:ss - msg`（`Utils.log()`）；stdout 纯净：深层杂散 `System.out` 改道 stderr。
- `--format text`：成功 `[+] ...`、失败 `[-] ...`、进度 `[*] ...` 上 stdout（信封不出）。
- 免责声明：`--help` 尾部与无参调用一次性输出（stderr）。

## 2. 命令词汇总表（CommandSpec 表驱动 → help 自动生成）

```
连接管理   add <type> | list | delete <id> | add-group <name> | delete-group <name>
任务       task list | task path | doctor | version | help [command]
通用(--id) info | exec <cmd> | sql "<sql>" | clean | revshell <ip> <port>
文件(--id) list-files <path> | read <file> | write <file> [content|--stdin]
           upload <local> <remote> | download <remote> [--out <local>] | rm <path> | mkdir <path>
类型专属   recovery (mssql) | deploy (mssql) | crontab/sshkey/rdb (redis)
```

> **冻结说明（相对 docs/2 §4.2 的一处改名）**：文件删除命令定名 `rm --id <id> <path>`；docs/2 §4.2 表中的 `delete <path>` 弃用——`delete` 保留给「删除连接记录」，避免一词二义。docs/2 §4.2 已由本文覆盖。

### 2.1 `add <type>`（type = mysql|mssql|postgresql|oracle|redis|mongodb）

```
add <type> --host H [--port P] [--user U] [--pass P] [--db D] [--memo M] [--group G]
           [--oracle-service]        # 仅 oracle：服务名模式（thin:@h:p/db）
           [--enc ENC]               # 连接级编码（存库，add 时决定；缺省随 -c）
```

| type | 端口缺省 | 用户缺省 | 库缺省 | 认证 |
|---|---|---|---|---|
| mysql | 3306 | root | （空） | user/pass |
| mssql | 1433 | sa | （空） | user/pass |
| postgresql | 5432 | postgres | postgres | user/pass |
| oracle | 1521 | system | orcl（SID；`--oracle-service` 时为服务名） | user/pass |
| redis | 6379 | — | — | 仅 `--pass` |
| mongodb | 27017 | — | admin | user/pass 可选 |

- `add` 即时做连通测试（`testConnection`）：**失败 → 删除刚插入记录 + exit 3（超时类 exit 4）+ 可操作 hint**（TC4 负控制验收语义）；成功 → 信封带 `"id"` 与 `data.tested=true`。
- 类型词支持别名：`mssql=sqlserver`、`postgresql=postgres/pg`、`mongodb=mongo`。

### 2.2 连接/组/任务管理

```
list [--group G]              # 信封 data=[{id,databasetype,ipaddress,port,username,database,memo,group,addtime}]; text=表格
delete <id>                   # 删连接记录（信封 id 回显）
add-group <name> | delete-group <name>
task list                     # 枚举 tasks-root 下任务（data=[{task,conns,db_size,dirty}])
task path                     # 当前 task 绝对路径
doctor                        # 自检（§4）
version                       # 版本+构建信息
```

### 2.3 通用操作（`--id <id>` 必带；`--id` 后置即可：`mdut exec --id 3 'id'`）

```
info                          # 基本信息探测，data 结构见 §3.1
exec [--method M] [--vps-host H --vps-port P] <cmd>
sql "<sql>"                   # 原生 SQL（mysql/mssql/pg/oracle 直通；redis/mongodb 不适用→exit 2）
clean                         # 清痕（各库语义 §3.4）
revshell <ip> <port>
```

`exec --method` 枚举（随库）：

| 库 | 可用 method | 缺省行为（无 --method） |
|---|---|---|
| mysql | （无；UDF 自动部署见 §3.2） | sys_eval 包装 |
| mssql | xpcmdshell / oap / agent / clr / **badpotato / godpotato / efspotato / efspotato_shellcode / sweetpotato**（M3a◆） | xpcmdshell（失败自动激活重试一次） |
| postgresql | （自动选路 low/udf/cve，`info.data.route` 可查） | 自动 |
| oracle | java / scheduler | java（缺函数自动导入 ShellUtil 重试一次） |
| redis | （无；模块部署用 `--vps-*`） | system.exec（需模块已加载） |

### 2.4 文件操作（`--id` 必带）

```
list-files <path>     read <file>        write <file> [content | --stdin]
upload <local> <remote>                  download <remote> [--out <local>]
rm <path>             mkdir <path>
```

各库路线与里程碑（M2=首批可用 / M3a=补全）：

| 命令 | mysql | mssql | postgresql | oracle | redis | mongodb |
|---|---|---|---|---|---|---|
| list-files | ★sys_eval `ls`（M3a） | ●xp_dirtree/CLR（M2） | ▲pg_ls_dir（M3a） | ●filerun listfile（M2） | ★system.exec ls（M3a） | — |
| read | ●LOAD_FILE（M3a） | ●spoa/CLR download（M2） | ▲pg_read_file（M3a） | ●filerun readfile（M2） | ★RDB 读回（M3a） | — |
| write | ●INTO DUMPFILE（M3a） | ●spoa/CLR upload（M2） | ★lo_export（M3a） | ●filerun writefile（M2） | ★RDB（M3a） | — |
| upload/download | ★sys_eval cat/dd（M3a） | ●（M2） | ★（M3a） | ●（M2） | ★（M3a） | — |
| rm / mkdir | ★sys_eval rm/mkdir（M3a） | ●spoa/CLR（M2） | ★sys_eval（M3a） | ●filerun（M2，无 mkdir→`-`） | ★system.exec（M3a） | — |

- `read` 内容 ≤ 64KB 时 base64 进 `data.b64`（信封 `"text"` 同时给可读截断）；`download --out` 直存本地文件（大文件纪律，stdout 信封只报字节数与路径）。
- `upload <local> <remote>`：本地文件直读直传；`write <file> --stdin` 从 stdin 读内容（配合管道）。

### 2.5 类型专属

```
recovery --id           # mssql：一键恢复组件（clearHistory + recoveryAll；M3a 扩 potato 卸载）
deploy  --id [--component clr]   # mssql：CLR 全链部署（trustworthy→activate→init→create func）
crontab --id <cron-line> [--path P]  # redis：写计划任务（cron 行显式传入，不内置回连文本）
sshkey  --id --pubkey K [--path P]   # redis：写 SSH 公钥（K=公钥原文）
rdb     --id --dir D --file F        # redis：设置持久化路径并 SAVE
```

## 3. 行为细则（dispatcher 级约定）

### 3.1 `info` 的 data 结构

| 库 | data 字段 |
|---|---|
| mysql | `version, os, arch, plugin_dir, sys_eval_exists` |
| mssql | `version, is_dba` |
| postgresql | `version, os, bits, route(low\|udf\|cve)` |
| oracle | `version, is_dba, os` |
| redis | `version, os, arch_bits, cves[]`（M3a◆ 扫描：未授权/弱口令/CVE-2022-0543/主从暴露） |
| mongodb◆ | `version, auth, databases[]`（M3a） |

### 3.2 自动部署链（dispatcher 责，Dao 业务零改动）

| 库 | 触发 | 动作 |
|---|---|---|
| mysql `exec` | 回显/异常含 `does not exist` | `getInfo→versionOutfile→Option→udf(sys_eval)` 后重试一次；再失败 exit 3 |
| mssql `exec --method xpcmdshell` | 异常含 `disabled`/xp_cmdshell 关闭 | `activateXPCS` 后重试一次 |
| mssql `exec --method clr` | `checkCLR()==false` | `setTrustworthy(db,on)→activateCLR→initCLR→createCLRFunc` 后执行 `clrruncmd`（type=1 提权位） |
| oracle `exec --method java` | 异常含 `ORA-00904` | `importShellUtilJAVA` 后重试一次；scheduler 权限不足（ORA-27486）→ hint |
| redis `exec` | 模块未加载（`system.exec` 报 unknown command） | 无 `--vps-*` → exit 3 + hint「先 `exec --vps-host .. --vps-port ..` 部署模块（需外部 rogue）」；带 `--vps-*` → `rogue()` 后执行（**不自动 clean**，用后 `clean` 是调用方义务） |
| postgresql `exec` | 按 `info.data.route` 选 `LowVersionEval/udfEval/cveEval`；udf 路线函数不存在 | 自动 `udf()` 部署后重试一次 |

### 3.3 `revshell`

| 库 | 路线 | 前置 |
|---|---|---|
| mysql | udf `backshell`（win_ex DLL；自动部署链同 §3.2） | — |
| mssql | —（M2 无原生；hint 用 exec 下载 payload） | — |
| postgresql | sys_eval 包装 `bash/nc`（M3a▲） | udf 已部署或 route=low |
| oracle | `shellrun('connectback', ip^port)` | ShellUtil 已导入（自动链） |
| redis | `system.rev` | 模块已加载（同 §3.2 hint） |

### 3.4 `clean` 语义

| 库 | 动作 |
|---|---|
| mysql | `cleanudf`：删 `*.temp` + drop sys_eval/backshell |
| mssql | `clearHistory`（关 xp_cmdshell/OAP、删 oashellresult、关 CLR）；组件完全卸载用 `recovery` |
| postgresql | `clear()`：drop sys_eval；cve 路线 drop cmd_exec（随执行自清） |
| oracle | `deleteShellFunction` + `deleteFileFunction` |
| redis | `clean()`：还原 dir/dbfilename/slave-read-only/slaveof、删 exp.so、卸模块、删 key |
| mongodb | —（info 只读，无痕可清；`clean` → exit 2） |

## 4. `doctor` 自检项（全部输出到 `data.checks[]`，单项 `{name,ok,detail}`）

1. `java`：运行时版本与 vendor（JDK 8+ 可用，8 为基线）。
2. `home`：jar 自身目录解析（`Utils.getSelfPath`），可写性。
3. `drivers`：`<home>/Driver/{mysql,mssql,oracle,postgresql}.jar` 存在且可读。
4. `plugins`：`<home>/Plugins/{Mysql,Mssql,Oracle,PostgreSql,Redis}` 存在（缺 MongoDB 目录不算失败）。
5. `task`：当前 task 目录存在、`data.db` 可开（`PRAGMA quick_check`）、audit 可写。
6. `proxy`：若带 `--proxy`，做一次 SOCKS5 握手连通检查（连代理端口）。
- 任一 fail → `ok:false` 且 exit 3；全过 → exit 0。

## 5. 并发与写锁（flock）

- **持锁命令**（变异目标侧，互踩风险）：`exec / clean / revshell / write / upload / rm / mkdir / deploy / recovery / crontab / sshkey / rdb`。
- 锁文件：`<task>/.lock`，`flock(LOCK_EX|LOCK_NB)`；拿不到 → 信封 `{"ok":false,"tool":..,"error":"task locked by another process","hint":"等待其它进程结束或改用 --task 隔离"}`，exit 5。
- **不持锁**：`add/list/delete/info/sql/read/list-files/download/task/doctor/version/help`（SQLite WAL + busy_timeout=5000 保证并发安全）。

## 6. task 与路径（wrapper 契约）

```
tasks-root = <jar目录>/tasks（冻结基点；`-Dmdut.tasks-root`/`$MDUT_TASKS_ROOT` 可移，wrapper 会同步注入）
                            # wrapper chdir 进 <tasks-root>/<task>/（相对 --out 等落任务目录，存储不受 cwd 影响）
<task>/data.db             # 首用即建；schema 与原版 data 表一致（22 列）+ 追加 groupname 列 + groups 表
<task>/logs/audit.jsonl    # {"ts":"...","task":"...","tool":"...","argv":[...],"exit":N,"ms":N,"ok":bool}
<task>/.lock               # flock 锁文件
```

- task 名守卫 `[A-Za-z0-9_-]{1,64}`（Java 侧兜底同 wrapper；违规 exit 2）。
- 解析优先级 `--task` > `$MDUT_TASK` > `default`；信封恒带实际生效 task。
- data.db 符号链接拒判、网络 fs（NFS/CIFS）拒判（wrapper 主责，Java 侧对 symlink 复核）。

## 7. 驱动与连接（JdbcProfiles 冻结值）

| 库 | 驱动文件 | 类名 | URL 模板（`{0}=host {1}=port {2}=db {3}=timeout(s×1000 由 Dao 处理)`） |
|---|---|---|---|
| mysql | `Driver/mysql.jar` | `com.mysql.cj.jdbc.Driver` | `jdbc:mysql://{0}:{1}/{2}?connectTimeout={3}&socketTimeout={3}&characterEncoding=utf-8&useSSL=false&serverTimezone=UTC&rewriteBatchedStatements=true` |
| mssql | `Driver/mssql.jar` | `net.sourceforge.jtds.jdbc.Driver` | `jdbc:jtds:sqlserver://{0}:{1}/{2};loginTimeout={3};socketTimeout={3}` |
| oracle | `Driver/oracle.jar` | `oracle.jdbc.driver.OracleDriver` | SID：`jdbc:oracle:thin:@{0}:{1}:{2}`；服务名：`jdbc:oracle:thin:@{0}:{1}/{2}`（另设 `oracle.jdbc.ReadTimeout/net.CONNECT_TIMEOUT`） |
| postgresql | `Driver/postgresql.jar` | `org.postgresql.Driver` | `jdbc:postgresql://{0}:{1}/{2}?loginTimeout={3}&socketTimeout={3}` |
| redis | — | Jedis 3.x 原生协议 | — |
| mongodb | — | mongodb-driver-sync 4.x | — |

- 加载只走 `Util.DriverLoader`（子 `URLClassLoader` + `driver.connect`）；禁 `(URLClassLoader)getSystemClassLoader()` 强转与 `regroupDrivers`。
- `--proxy socks5://`：进程级 `socksProxyHost/Port/Version=5` + `Authenticator`；对 Oracle thin/jTDS 实测结论记入 §10 矩阵，不生效库在错误 hint 给外部转发兜底建议。

## 9. 验收基线（对应 AGENTS.md §2.5 / §4）

1. `mvn -f MDAT-DEV/pom.xml clean package` 产出 `MDAT-DEV/target/mdut.jar`（uber-jar）。
2. jar 内零 javafx / 零 `Driver/`、`Plugins/`、`*.fxml`、零 data.db（`unzip -l` 断言）。
3. `java -jar mdut.jar version` → 一行信封；无参 → 用法 + 免责 + exit 2。
4. `cli/tests/` golden：给定 argv → 断言信封形状 + 退出码（含 2/3/4/5 全触发）。
5. task 隔离：两 task 各自 add 同端口目标，`list` 互不可见；并发 add 同 task 不锁死。
6. 写锁：持锁命令并发第二进程 → exit 5。
7. 实验室 TC1–TC4（AGENTS.md §4.1）改造完成后必测。

|---|---|---|
