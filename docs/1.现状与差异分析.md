## 0. 结论摘要

1. **deepstrike 侧对 MDUT 的依赖面极窄**：全部运行时交互收敛在 `packages/exploit/mdut.ts` 一个文件（95 行）——argv 构造 + 输出文本解析 + 超时，通过 `java -jar <jar> <args>` 子进程调用；状态（连接库）完全落在 jar 同目录的 `data.db`，deepstrike 不持有任何 MDUT 状态。
2. **deepstrike 现行集成的技术约束是「argv 形状 + 输出文本约定」**：`add <type> -h -P [-u -p -d] -m` / `list` / `delete <id>` / `--id <id> <子命令> [--method m] [args...]`，以及成功输出含 `ID: <数字>`、错误可被 `looksLikeError` 正则区分。这些被 `tests/exploit.test.ts` 的罐头样例与正则逐字锁定。（注：v2 方案已解除该兼容红线——重构完成后由 deepstrike 适配迁移，本节契约降级为迁移参考，见《2.CLI二开实施方案》§0.2/§11。）
3. **本仓库 `main` 分支没有任何 CLI 代码**——它是纯 JavaFX GUI 原版（v2.1.1）。现网 Extend-1.3.1 jar 是第三方在原版源码上做的「GUI+CLI 混合」二开：加了 `cli.CliMain` 入口、`TextOutput` 输出抽象、MongoDB 支持、Redis CVE 扫描、MSSQL potato 系列扩展。**我们的二开要做同样的事，但做得更彻底（纯 CLI 可选 + 结构化输出 + 可维护性）**。
4. **上游已有 v3 方向可参照但不可依赖**：`origin/v3` 分支是 hanc00l 用 Go + Wails + React 的全闭源重写（仓库内只有发布物与文档），提供 MCP 24 工具、全数据库 SOCKS5 代理、Redis Relay。其功能清单是二开增强面的最佳参照，但源码不可用，不能作为二开基座。
5. **二开最大的工程量在「Dao 层 GUI 解耦」**：Dao 直接从 `ControllersFactory` 取 JavaFX Controller 并向 `TextArea.appendText` 写日志（`Platform.runLater`），必须改造为输出回调抽象后才能被 CLI 复用。现网 jar 已验证这条路可行（其 `Util.TextOutput`/`CliOutput`/`GuiOutput` 就是该抽象）。
6. **deepstrike 记录的两个实战教训必须在新 CLI 里正面解决**：① Java 程序不支持 SOCKS → 内网目标必须先 `channel_forward` 转发（或新 CLI 原生支持代理，`data.db` 已预留 proxy 字段位）；② Redis 主从复制 RCE 依赖外部 rogue server 与预编译 `exp.so`。

**HTTP 隧道（`Dao/{Mysql,Mssql,PostgreSql,Oracle}HttpDao.java`，共 2569 行）**：v2.1.0 新增（`CHANGELOG.md`）。把 SQL/命令经 HTTP POST 隧道到目标 Web 上的隧道脚本（`Plugins/Template/*_tunnel.{php,aspx,jsp}`）。**协议是 MDUT 自研的极简方案（非哥斯拉/冰蝎）**：POST 参数名=密钥本身，值=`Base64(XOR(明文, key))`（`Util/Base64XOR.java:110-116` 逐字节循环异或），明文格式 `ip:port|user|pass|db|Base64(SQL)`（MSSQL 版多一段 `|timeout`，`MssqlHttpDao.java:744-749`）；响应同加密回传，约定 `Status | True`=成功、`ERROR://` 前缀=异常（`mysql_tunnel.php:46-66`）。连接记录的 `url`/`encryptionkey` 列即为此服务。客户端网络栈 `Util/OKHttpUtil.java` 信任所有证书 + 约 60 条 UA 池随机（`Util/Utils.java:26-128`）+ **支持 HTTP/SOCKS5 代理及代理认证**（`OKHttpUtil.java:74-79`）。Redis 不支持隧道（v2.1.0 变更日志明示）。**现网 Extend CLI 未暴露 HTTP 隧道**（`--help` 无对应子命令），这是原版有而现网 CLI 没有的功能面。

### 2.3 数据持久化（data.db）

- 位置：`Utils.getSelfPath()`（jar 自身路径）同目录的 `data.db`（`Dao/ManagerDao.java:17-31`），表 `data`（连接记录，22 列）与 `group`（分组）。
- 表 `data` 关键列：`id`（自增主键 = 对外 connection_id）、`databasetype/ipaddress/port/username/password/database/timeout/memo/addtime`、HTTP 隧道列（`ishttp/url/encryptionkey/httpheaders/connecttype`）、**代理列（`isproxy/proxytype/proxyaddress/proxyport/proxyusername/proxypassword`，原版数据模型已预留代理位，GUI 的 AddAndEdit 支持配置）**、`group`。
- 与现网 `/opt/tools/MDUT/data.db` 实测 schema 完全一致 → **沿用该 schema 可直接继承现网已保存的连接（实战资产迁移零成本）**。

### 2.4 驱动加载机制（二开兼容性要点）

每个 Dao 构造器：读 `config.yaml`（jar 同目录）→ 拿 `Driver` 路径 → 反射 `ClassLoader.getSystemClassLoader()` 强转 `URLClassLoader` 调 `addURL` → `Class.forName`（`Dao/MysqlDao.java:53-74`）。连接前 `Utils.regroupDrivers()` 把当前驱动排到 `DriverManager` 队列首位，避免多驱动时 URL 误配（`Util/Utils.java:458-483`）。

⚠️ **该机制只在 Java 8 可用**（Java 9+ 系统 类加载器不再是 `URLClassLoader`，强转即 `ClassCastException`）。本机默认 `java` 为 1.8.0_482（Zulu 8，另有 11/21/25），现网 jar 也是 Build-Jdk 1.8——二开若想支持新 JDK 必须改造驱动加载（详见实施方案 D5 决策点）。

### 2.7 其他行为（二开需知）

- 日志格式：`Utils.log()` → `[*] yyyy-MM-dd HH:mm:ss - <msg>\n`（`Util/Utils.java:223-229`）——deepstrike 注释「时间戳日志走 stderr」的出处。
- 自更新：`Controller/UpdateController.java` 手动触发时 GET `api.github.com/repos/SafeGroceryStore/MDUT/releases/latest`（`Util/Utils.java:534-566`）→ `HttpUtil.downloadFile` 下载到 jar 目录，提示手动替换；**无静默自更新**（autoUpdate 选项代码被注释，`SettingController.java:205,211`）。CLI 形态应整体裁掉该面，消除运行期外联。
- 已知缺陷（二开时顺手修复，出处见《[附录A](./附录A.MDUT原版功能分析报告-全量证据.md)》§I）：
  1. `PostgreSqlDao.java:76` `regroupDrivers("ostgresql")` 少个 `p`，导致 Pg 驱动排序失效；
  2. `MysqlDao.java:176` 读 UDF hex 未 `replace("\n","")`（HTTP 版有），带换行的 hex 写库可能损坏；
  3. `RedisDao` 的 `CONN/dir/slaveReadOnlyFlag` 是 `static`（`RedisDao.java:23-25`），多连接不安全，CLI 串行调用下无碍但需知悉；
  4. `Utils.splitDisk` 以路径含 `:` 判 Windows（`Utils.java:489-502`），Linux 含冒号路径误判；`splitHeaders` 严格 `K: V` 否则越界（`:509-518`）；
  5. 线程模型：每按钮 `new Thread` + 窗口关闭 `Thread.stop()` 强杀（`MainController.java:452-470`，废弃 API），CLI 应改受控执行（超时中断）；
  6. 依赖老化：fastjson 1.2.83 / snakeyaml 1.28 / pegdown 停更 / jjwt 0.9.1，org.json 与 fastjson 混用（`pom.xml:28-101`）。
- UA 池：`Util/Utils.java:100-133` 内置约 60 条 Chrome UA（HTTP 隧道伪装用）。

## 3. 现网 MDUT-CLI.jar（Extend-1.3.1）解析

## 4. deepstrike 现行集成契约（2026-09 快照；v2 方案起仅作后续适配迁移的参考，非红线）

> 证据均在 `/opt/deepstrike`；完整引用清单见《2.CLI二开实施方案》附录 A。

### 4.1 调用通路

- 唯一封装：`packages/exploit/mdut.ts`（`MdutClient`）。每次调用拉起 `java -jar <mdutJarPath> <args...>`（cwd=mdutWorkDir），合并 stdout/stderr，`code ?? -1`。
- 执行器：`ctxShellExecutor`（`webshell/executor.ts:24-37`）把 argv 拼成 `cd '<cwd>' && 'java' '-jar' '<jar>' …`（单引号转义）走 dsh shell 运行时——**netscope 以 replace-shell 挂载时子进程出站受 nft 白名单强制，新 CLI 不能绕开 bash -c 通路**。
- 装配：dsh 侧 `exploit/index.ts`（Config：`mdutJarPath` 默认 `/opt/tools/MDUT/MDUT-CLI.jar`、`mdutWorkDir` 默认 `/opt/deepstrike/var/mdut`）；ms 侧 `mcp/main.ts:54`（环境变量 `DEEPSTRIKE_MDUT_JAR`）；两处均可在 `cordis.patch.yml:40-41` 覆盖。
- 超时链：MdutClient connect 60s / list·delete 30s / info·exec·special 120s → 工具声明 180s → MCP 兜底 300s。

### 4.3 输出契约

- add 成功必须含 `ID: <数字>`（解析正则 `/—\s*ID:\s*(\d+)|ID:\s*(\d+)/`；现网样例 `Added mysql connection 127.0.0.1:1 — ID: 87`）。

- 工具描述有 5 处子串回归锚点（「不支持 SOCKS」「channel_forward」「redis-rogue-server.py」「主从复制」「exp.so」），重写描述必须保留。

### 4.4 状态契约

- 连接库固定落 **jar 同目录** `data.db`（`mdut.ts:8` 注释 + 实测 workDir 为空而 data.db 有实战写入）；connection_id 即 `data.id`，跨调用、跨 daemon 重启复用。
- deepstrike 不读库、只透传 ID 字符串——**兼容现网 data.db schema 即可无缝继承已保存连接**。

### 4.5 模型面（db_exploit 工具）

- 参数：`action`（enum 7 值）/ `db_type`（enum 6 类含 mongodb）/ host/port/user/pass/database/connection_id/cmd/subcommand/args/method。

## 6. 关键风险与既知坑（来自 deepstrike 实战记录）

1. **SOCKS 不支持 → NoRouteToHost**：MDUT 直连不可路由内网必然失败，Java 异常栈对 LLM 无行动价值（用例 2 实录）。现网以「channel_forward 转发 + 127.0.0.1 直连」约定规避，且被 `exploit.test.ts:142-153` 与 `channel.test.ts:328-330` 双向锁定。新 CLI 若原生支持代理，需同步修订两侧描述锚点与测试。
2. **Redis 主从复制的坑**：高版本 gcc 自编译 exp.so 会让 redis 4.0.14 崩溃；载荷是裸 so、握手为 inline 协议；deepstrike 用内置 `redis-rogue-server.py` + MSF 预编译 exp.so 的范式（工具描述锁定）。新 CLI 的 redis 路线必须与该范式兼容（rogue server 仍是外部进程、`--vps-host/--vps-port` 语义不变）。
3. **mysql exec 语义**：UDF 部署后 `exec` 传 shell 命令原文、由 MDUT 自动包 `SELECT sys_eval(...)`——工具描述明示「不要再自己写 SELECT sys_eval」。新 CLI 不得改变该语义。
4. **长驻操作与超时链**：rogue/revshell 类操作在 60/120s 超时链下由 dsh shell 运行时杀进程；rogue server 本身必须外部常驻（bash 起 python 脚本），CLI 内不可阻塞等待。
5. **data.db 明文存凭据**：现状即如此（现网 data.db 实战写入），替换不改变该风险面，但文档需明示。
